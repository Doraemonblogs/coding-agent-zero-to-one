# 中文提交

按下面的步骤，把当前的改动整理成一次 Git 提交。

## 步骤

1. 运行 `git status` 和 `git diff --stat`，了解改了哪些文件。
2. 如果没有任何改动，告诉用户"没有需要提交的改动"，然后停止。
3. **安全检查**：如果改动里出现了 `.env`、`*.key`、`*.pem`、`id_rsa`，或者文件内容里有类似 `sk-`、`api_key`、`password`、`secret` 的密钥，**停下来提醒用户**，不要提交这些文件，并建议把它们加进 `.gitignore`。
4. 运行 `git diff`（必要时加上 `--staged`）阅读具体改动，理解这次改动做了什么。
5. 按下面的格式写提交说明，先展示给用户看：

   ```
   <类型>：<一句话说明做了什么>

   - <具体改动 1>
   - <具体改动 2>
   ```

   类型从这几个里选：`新功能`、`修复`、`优化`、`样式`、`文档`、`重构`、`其他`。
   第一行不超过 30 个字，说清楚"做了什么"，不要写"修改了文件"这种没有信息量的话。
6. 运行 `git add -A` 和 `git commit`，使用上面的提交说明。
7. 最后运行 `git log --oneline -1`，把结果告诉用户。

## 示例

```
新功能：时钟页面显示日期和星期

- 在时钟下方增加日期行，格式为"2026 年 9 月 29 日 星期二"
- 日期随时间自动更新
```
